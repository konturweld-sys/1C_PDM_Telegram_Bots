# Интерфейсы PDM-адаптеров Telegram

Целевая платформа: 1С:Предприятие 8.3.12.1529. Реализация — только в расширении «Интеграция».

## Контракт ошибок

Функции, возвращающие структуру, используют поля `Успех`, `КодОшибки`, `ТекстОшибки`, `Данные`. Фатальные ошибки контракта могут завершаться исключением. Токены, SMTP-пароли, секретные заголовки и полные URL с секретами не включаются в сообщения и журнал. Все проверки прав выполняются на сервере перед операцией.

## ПДМ_УБТ_ОбщиеФункции

- `КодОсновногоЯзыка() -> Строка` — клиент/сервер; код основного языка PDM.
- `РазделениеВключено() -> Булево` — сервер; для текущей однобазовой схемы возвращает Ложь.
- `ПутьКТабличнойЧасти(ПутьТЧ, НомерСтроки, ИмяПоля) -> Строка` — клиент; строит путь к реквизиту строки табличной части.
- `ПриНачалеВыполненияРегламентногоЗадания(МетаданныеЗадания)` — сервер; инициализация контекста фонового задания.
- `СообщитьПользователю(Текст, КлючДанных, Поле, ПутьКДанным, Отказ)` — клиент/сервер; адаптер уведомления PDM.

## ПДМ_УБТ_РегламентныеЗадания

- `НайтиЗадания(Отбор) -> Массив<Структура>` — сервер.
- `ДобавитьЗадание(Параметры) -> Структура` — сервер; возвращает идентификатор/ссылку и результат.
- `ИзменитьЗадание(Задание, Свойства) -> Структура` — сервер.
- `УдалитьЗадание(Задание) -> Структура` — сервер.

Идемпотентный ключ: имя задания + идентификатор владельца. Повторное создание не порождает дубль.

## ПДМ_УБТ_ЗащищенноеХранилище

- `ЗаписатьТокенБота(UUIDБота, Токен)` — серверная процедура.
- `ПрочитатьТокенБота(UUIDБота) -> Строка` — только сервер.
- `УдалитьТокенБота(UUIDБота)` — серверная процедура.

Ключ шифрования не размещается рядом с шифротекстом. Конкретный алгоритм и размещение ключа фиксируются после проверки средств платформы и инфраструктуры. Клиенту токен не передаётся.

## ПДМ_УБТ_Права

- `ИзменениеРазрешено(Ссылка) -> Булево` — сервер.
- `ВыполнениеПроизвольногоКодаРазрешено() -> Булево` — сервер.

Право консоли не включается автоматически в роль администратора ботов.

## ПДМ_УБТ_Отчеты

`СформироватьОтчет(СсылкаВарианта, ПараметрыФормирования) -> Структура`, сервер. Поля результата: `Успех, ТабличныйДокумент, СсылкаВарианта, НаименованиеФайла, Расширение, ТекстОшибки, КодОшибки`.

## ПДМ_УБТ_Email

`ОтправитьЭлектронноеСообщение(ПараметрыОтправки) -> Структура`, сервер. Поля: `Успех, ИдентификаторСообщения, СтатусыПолучателей, ТекстОшибки, КодОшибки`. Реализация будет завершена после аудита реального SMTP-модуля PDM.

## ПДМ_УБТ_ПредставлениеОтчетов

- `ПодготовитьВложение(РезультатОтчета, ФорматФайла) -> Структура` — сервер; поля: `Успех, ИмяФайла, Расширение, ДвоичныеДанные, Размер, ТекстОшибки`.
- `ПоказатьРезультатОтчета(РезультатОтчета)` — клиент; отображение/экспорт без автоматической отправки.

## ПДМ_УБТ_ОчередьСообщений

- `ОбработатьОчередь(ЛимитПакета)` — сервер; выбор, блокировка, отправка и фиксация результатов.
- `ПовторитьОтправку(Сообщение)` — сервер; проверяет права и повторяет только неуспешные доставки.

## Обязательные уточнения до снятия заглушек

1. Сверить платформенный API менеджера регламентных заданий именно для 8.3.12.1529.
2. Разобрать SMTP-код PDM и защищённое хранение SMTP-пароля.
3. Утвердить криптографическую схему хранения токенов.
4. Сверить реальный механизм вызова и настройки отчётов PDM.
5. Подтвердить сигнатуру `ОбщегоНазначенияКлиентСервер.СообщитьПользователю`.

Все BSL-файлы этого этапа — безопасные заглушки с исключением «Реализация не завершена»; они не предназначены для эксплуатации до последующей реализации.
