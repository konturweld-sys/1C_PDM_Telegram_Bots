# Полные контракты PDM-адаптеров Telegram

Версия спецификации: 0.2.0. Целевая платформа: 1С:Предприятие 8.3.12.1529. Размещение: расширение «Интеграция». Основная конфигурация PDM не изменяется.

## Общие соглашения

1. Все операции чтения/записи метаданных и внешних соединений выполняются на сервере.
2. Клиентские модули не получают Telegram-токены, SMTP-пароли, закрытые ключи или секретные заголовки.
3. Методы, возвращающие результат бизнес-операции, используют структуру:
   - `Успех: Булево`;
   - `КодОшибки: Строка`;
   - `ТекстОшибки: Строка`;
   - `Данные: Произвольный`.
4. Для неверной формы входных параметров и нарушений инвариантов допускается контролируемое исключение. Ошибки внешних систем возвращаются в результате операции, если вызывающий код должен принять решение о повторе.
5. Запись в журнал регистрации не должна содержать токены, пароли, секретные заголовки, полные URL с секретами и полное тело запроса, если оно может содержать персональные или секретные данные.
6. Временные заглушки, которые сейчас находятся в BSL-файлах, не являются реализацией этих контрактов. Их вызов до снятия заглушек завершится исключением.

## 1. ПДМ_УБТ_ОбщиеФункции

### 1.1 КодОсновногоЯзыка

- Сигнатура: `Функция КодОсновногоЯзыка() Экспорт`.
- Контекст: клиент и сервер.
- Вход: нет.
- Возврат: строка кода основного языка PDM. В текущей русскоязычной конфигурации возвращает `ru`.
- Ошибки: отсутствуют при неизменном основном языке; при смене основного языка адаптер необходимо пересмотреть.

### 1.2 РазделениеВключено

- Сигнатура: `Функция РазделениеВключено() Экспорт`.
- Контекст: сервер.
- Вход: нет.
- Возврат: Булево.
- Для текущей однобазовой PDM-инсталляции возвращает Ложь. Не имитирует режим разделения данных.

### 1.3 ПутьКТабличнойЧасти

- Сигнатура: `Функция ПутьКТабличнойЧасти(ПутьТЧ, НомерСтроки, ИмяПоля) Экспорт`.
- Контекст: клиент.
- Вход:
  - `ПутьТЧ`: Строка, путь к табличной части в данных формы;
  - `НомерСтроки`: Число, индекс строки;
  - `ИмяПоля`: Строка, имя реквизита строки.
- Возврат: строка пути к конкретному полю строки табличной части.
- Ошибки: пустой путь, отрицательный индекс или пустое имя поля — контролируемая ошибка.
- Статус: формат индекса и итоговой строки должен быть подтверждён по всем местам вызова исходной библиотеки до реализации.

### 1.4 ПриНачалеВыполненияРегламентногоЗадания

- Сигнатура: `Процедура ПриНачалеВыполненияРегламентногоЗадания(МетаданныеЗадания) Экспорт`.
- Контекст: сервер.
- Вход: объект метаданных регламентного задания.
- Возврат: нет.
- Поведение: проверяет, что вызов относится к заданию библиотеки и что задача не отключена настройками PDM. Не вызывает отсутствующий ERP/BSP модуль.
- Ошибки: неизвестное задание или отключённая функциональность — исключение с безопасным текстом.

### 1.5 НовоеЗащищенноеСоединение

- Сигнатура: `Функция НовоеЗащищенноеСоединение() Экспорт`.
- Контекст: сервер.
- Вход: нет.
- Возврат: объект платформы `ЗащищенноеСоединениеOpenSSL` с настройками TLS по умолчанию. Клиентские сертификаты не используются.
- Ошибки: ошибка инициализации TLS передаётся вызывающему коду.

### 1.6 СообщитьПользователю

- Сигнатура: `Процедура СообщитьПользователю(Текст, КлючДанных = Неопределено, Поле = "", ПутьКДанным = "", Отказ = Ложь) Экспорт`.
- Контекст: клиент/сервер.
- Вход: текст, необязательный ключ данных, имя поля, путь к данным и флаг отказа.
- Возврат: нет; базовая PDM-процедура устанавливает `Отказ = Истина` после показа сообщения.
- Реализация уже делегирует вызов `ОбщегоНазначенияКлиентСервер.СообщитьПользователю` с той же сигнатурой.

## 2. ПДМ_УБТ_РегламентныеЗадания

Все методы серверные. Для управления используется платформенный менеджер `РегламентныеЗадания`, а не ERP/BSP-модуль.

### 2.1 НайтиЗадания

- Сигнатура: `Функция НайтиЗадания(Отбор) Экспорт`.
- Вход: Структура отбора. Поддерживаемые ключи платформенного менеджера: `Метаданные`, `Ключ`, `Использование`, `Наименование`, `Предопределенное`, `УникальныйИдентификатор`.
- Возврат: Массив объектов регламентных заданий платформы.
- Ошибки: неверный тип отбора — контролируемое исключение; ошибка доступа — результат/исключение без обхода прав.

### 2.2 ДобавитьЗадание

- Сигнатура: `Функция ДобавитьЗадание(Параметры) Экспорт`.
- Вход: Структура:
  - `МетаданныеЗадания`: ОбъектМетаданных.РегламентноеЗадание, обязательно;
  - `Ключ`: Строка, обязательный для параметризованного экземпляра;
  - `Параметры`: Массив параметров обработчика;
  - `ИдентификаторПользователяИБ`: UUID пользователя 1С;
  - `Расписание`: РасписаниеРегламентногоЗадания;
  - `Наименование`: Строка;
  - `Использование`: Булево.
- Возврат: Структура результата с `Успех`, `Задание`, `УникальныйИдентификатор`, `Создано`, `КодОшибки`, `ТекстОшибки`.
- Поведение: сначала ищет экземпляр по `МетаданныеЗадания + Ключ`; если найден один — обновляет его; если не найден — создаёт. Несколько совпадений — ошибка целостности, автоматическое удаление дублей запрещено.
- Пользователь: UUID сопоставляется через `ПользователиИнформационнойБазы.НайтиПоУникальномуИдентификатору()`. Отсутствующий пользователь — ошибка.
- Ошибки платформы не подавляются; результат содержит безопасное описание без паролей/токенов.

### 2.3 ИзменитьЗадание

- Сигнатура: `Функция ИзменитьЗадание(Задание, Свойства) Экспорт`.
- Вход:
  - `Задание`: объект регламентного задания, ранее полученный через НайтиЗадания;
  - `Свойства`: структура с любым подмножеством полей `Параметры`, `ИдентификаторПользователяИБ`, `Расписание`, `Наименование`, `Использование`.
- Возврат: Структура результата.
- Поведение: меняет только явно переданные свойства, затем записывает объект.
- Ошибки: Неопределено/неподдерживаемый тип задания, неизвестное свойство, недоступный пользователь или ошибка записи.

### 2.4 УдалитьЗадание

- Сигнатура: `Процедура УдалитьЗадание(Задание, Владелец) Экспорт`.
- Вход: объект регламентного задания и ссылка владельца.
- Возврат: нет.
- Поведение: параметризованный экземпляр удаляется методом платформенного объекта. Предопределённое задание не удаляется: его использование отключается.
- Ошибки: попытка удалить неизвестное/предопределённое задание без возможности отключения — контролируемая ошибка.

## 3. ПДМ_УБТ_ЗащищенноеХранилище

Все методы — только сервер. Реализация использует штатный интерфейс PDM `ОбщегоНазначения`:
`ЗаписатьДанныеВБезопасноеХранилище`, `ПрочитатьДанныеИзБезопасногоХранилища` и `УдалитьДанныеИзБезопасногоХранилища`.

- Владелец данных: строковый идентификатор `"УБТ_Бот_" + Строка(UUIDБота)`. Он сохраняет совместимость с ранее записываемыми токенами.
- Ключ данных: `"Пароль"` (ключ по умолчанию штатного безопасного хранилища), поэтому ранее записанные значения остаются читаемыми.
- Каждая операция выполняется в привилегированном режиме только на время обращения к штатному хранилищу; при исключении привилегированный режим отключается до повторного выброса исключения.
- Отдельный ключ шифрования библиотекой не создаётся и не хранится. Защита и ограничения определяются реализацией штатного безопасного хранилища PDM.
- Регистр `ПДМ_УБТ_ЗащищенныеДанныеБотов` не используется этими методами и не является источником токенов.

### 3.1 ЗаписатьТокенБота

- Сигнатура: `Процедура ЗаписатьТокенБота(UUIDБота, Токен) Экспорт`.
- Вход: UUID бота и непустая строка токена.
- Возврат: нет.
- Поведение: записывает/заменяет значение по ключу `"Пароль"` для владельца бота.
- Ошибки: не задан UUID, пустой токен или ошибка штатного хранилища.

### 3.2 ПрочитатьТокенБота

- Сигнатура: `Функция ПрочитатьТокенБота(UUIDБота) Экспорт`.
- Вход: UUID бота.
- Возврат: сохранённая строка токена либо `Неопределено`, если значение отсутствует; вызов только на сервере.
- Ошибки: не задан UUID или ошибка штатного хранилища.
- Обязательное поведение вызывающего кода: не возвращать токен на клиент, не сохранять его в реквизитах формы, структуре ответа HTTP или журнале; использовать только на время запроса Telegram.

### 3.3 УдалитьТокенБота

- Сигнатура: `Процедура УдалитьТокенБота(UUIDБота) Экспорт`.
- Вход: UUID бота.
- Возврат: нет.
- Поведение: удаляет данные владельца из штатного безопасного хранилища.
- Ошибки: не задан UUID или ошибка штатного хранилища.

## 4. ПДМ_УБТ_Права

Все методы серверные; проверки выполняются перед операцией, а не только в форме.

### 4.1 ИзменениеРазрешено

- Сигнатура: `Функция ИзменениеРазрешено(Ссылка) Экспорт`.
- Вход: ссылка на объект Telegram-библиотеки.
- Возврат: Булево.
- Проверяет права на изменение соответствующего объекта и роль администратора ботов.
- Ошибка проверки прав не должна трактоваться как разрешение.

### 4.2 ВыполнениеПроизвольногоКодаРазрешено

- Сигнатура: `Функция ВыполнениеПроизвольногоКодаРазрешено() Экспорт`.
- Вход: нет.
- Возврат: Булево.
- Проверяет отдельную роль администратора консоли. Роль администратора ботов сама по себе недостаточна.

## 5. ПДМ_УБТ_Отчеты

- Сигнатура: `Функция СформироватьОтчет(СсылкаВарианта, ПараметрыФормирования) Экспорт`.
- Контекст: сервер.
- Вход:
  - `СсылкаВарианта`: СправочникСсылка.ПДМ_УБТ_ВариантыОтчетов;
  - `ПараметрыФормирования`: Структура значений параметров отчёта.
- Возврат: Структура `Успех`, `ТабличныйДокумент`, `СсылкаВарианта`, `НаименованиеФайла`, `Расширение`, `Расширения` (массив), `КодОшибки`, `ТекстОшибки`. Формирование использует схему СКД отчёта PDM, настройки варианта из `ХранилищеЗначения` или настройки по умолчанию.
- Поведение: проверяет существование отчёта и доступность варианта, формирует отчёт на сервере, не отправляет файл.
- Ошибки: неизвестный отчёт, неверные параметры, ошибка компоновки/формирования, недопустимый формат.

## 6. ПДМ_УБТ_Email

- Сигнатура: `Функция ОтправитьЭлектронноеСообщение(ПараметрыОтправки) Экспорт`.
- Контекст: сервер.
- Вход: Структура:
  - `Получатели`: Массив адресов;
  - `Тема`: Строка;
  - `Текст`: Строка;
  - `Формат`: формат сообщения;
  - `Вложения`: Массив структур `ИмяФайла, Расширение, ДвоичныеДанные`;
  - `ПрофильПочты`: ссылка на профиль PDM либо Неопределено для основного профиля уведомлений.
- Возврат: Структура `Успех`, `ИдентификаторСообщения`, `СтатусыПолучателей`, `КодОшибки`, `ТекстОшибки`.
- Поведение: использует SMTP-профиль PDM, подключается на сервере, отправляет письмо, фиксирует результат по каждому получателю.
- Ошибки: отсутствует профиль, неполные SMTP-настройки, ошибка подключения, отказ SMTP, ошибка вложения. Пароль профиля не копируется в новый регистр и не возвращается клиенту.

## 7. ПДМ_УБТ_ПредставлениеОтчетов

- `Функция ПодготовитьВложение(РезультатОтчета, ФорматФайла) Экспорт` — сервер; возвращает структуру `Успех, ИмяФайла, Расширение, ДвоичныеДанные, Размер, КодОшибки, ТекстОшибки`.
- `Процедура ПоказатьРезультатОтчета(РезультатОтчета) Экспорт` — клиент; показывает табличный документ/предлагает экспорт, не выполняет отправку и не хранит секреты.
- Ошибки конвертации/формирования возвращаются в результате; клиент получает безопасный текст.

## 8. ПДМ_УБТ_ОчередьСообщений

- `Процедура ОбработатьОчередь(ЛимитПакета = 50) Экспорт` — сервер; пакетная обработка очереди. Метод используется регламентным заданием и не должен требовать обязательных параметров.
- `Процедура ПовторитьОтправку(Сообщение) Экспорт` — сервер; проверяет право оператора, повторяет только неуспешные доставки.
- Для каждого получателя фиксируются попытка, статус, дата, внешний идентификатор и безопасное описание ошибки.
- Повторная отправка не должна повторять успешную доставку; блокировка/идемпотентность обязательна.

## Платформенные основания

- Для создания и чтения заданий используется платформенный менеджер `РегламентныеЗадания`: `СоздатьРегламентноеЗадание`, `ПолучитьРегламентныеЗадания`, `НайтиПоУникальномуИдентификатору`; объект задания поддерживает `Записать()` и `Удалить()`. Использование привилегированного режима допускается только после серверной проверки прав.
- Для уведомлений используется PDM `ОбщегоНазначенияКлиентСервер.СообщитьПользователю(ТекстСообщенияПользователю, КлючДанных = Неопределено, Поле = "", ПутьКДанным = "", Отказ = Ложь)`.
- Для пользователя регламентного задания UUID сопоставляется с пользователем информационной базы через `ПользователиИнформационнойБазы.НайтиПоУникальномуИдентификатору()`.

## Что остаётся неутверждённым

1. Точный способ получения кода основного языка PDM.
2. Формат пути к полю табличной части и база индекса строки.
3. Проверка совместимости штатного безопасного хранилища PDM с целевой платформой 8.3.12.1529 и подтверждение его наличия в конкретной базе.
4. Точные параметры формирования конкретных отчётов PDM.
5. Конкретный способ отправки вложений по SMTP через PDM с учётом ограничения платформы 8.3.12.1529.


Формирование СКД реализуется штатным конвейером платформы: схема → настройки → `КомпоновщикМакетаКомпоновкиДанных` → `ПроцессорКомпоновкиДанных` → `ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент`. Этот процессор доступен на сервере и возвращает табличный документ. См. официальную методическую публикацию 1С: <https://its.1c.ru/db/content/metod8dev/src/platform81/metod/dcs/i8103622.htm>.
